= Fichiers
include::_fpsot-terms.adoc[]

Ces règles nomment les fichiers et les dossiers d'un dépôt de spécification de la {abbr-fpsot-first}.

[[NAM-070]]
*NAM-070.* Dans un dépôt de spécification, un nom de fichier ou de dossier DOIT être en kebab-case et en anglais.
Son extension DOIT être en minuscules.
Une page DOIT avoir le même nom de fichier anglais dans chaque dossier de langue, comme `spec/fr/code-lists.adoc`.
Un fichier dont un outil ou une convention fixe le nom garde ce nom, comme `README.adoc`, `SKILL.md` ou `_fpsot-terms.adoc`.
La spécification de documentation exige déjà un seul nom de fichier pour les deux langues.
Les minuscules évitent des erreurs sur les systèmes de fichiers qui ignorent la casse.

[[NAM-071]]
*NAM-071.* Un diagramme rendu DOIT avoir le même nom de base que sa source, comme `branch-model.puml` et `branch-model.svg`.
On trouve alors la source de chaque image.

[[NAM-072]]
*NAM-072.* Dans tout dépôt, un fichier de fonctionnalité Gherkin DOIT avoir un nom anglais en kebab-case, avec l'extension `.feature`.
Ses versions anglaise et française DOIVENT avoir le même nom de fichier, comme `features/en/record-a-person.feature` et `features/fr/record-a-person.feature`.
La spécification sur les tests fixe où vont les deux versions et comment elles restent en accord.
Un seul nom permet à un outil d'associer les deux versions de chaque fonctionnalité.
