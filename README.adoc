= FPSOT naming specification

This specification sets how FPSOT projects name the identifiers that machines read.
It covers repositories, Java and Kotlin packages, Maven coordinates, address paths, JSON fields and query parameters, event types, code lists and file names.
Names are in English, and people see translated labels.

== Implement this spec

Read the normative text in `spec/en/` or `spec/fr/`.
Each requirement has an ID, such as `NAM-001`.
Check every name you publish against each requirement.
`skill/SKILL.md` gives a one-page summary.

== Adopt this spec

Read the guides in `docs/modules/en/pages/` or `docs/modules/fr/pages/`.
They explain why names stay in English and show how to choose a name.
To require the spec in a contract, cite its version and the requirement IDs.

== Layout

[cols="1,3"]
|===
| Folder | Content

| `spec/`
| Normative text, in English and French. `book.adoc` joins the pages into one book.

| `docs/`
| Guides, in the Antora folder layout.

| `skill/`
| The agent skill: a short summary that cites requirement IDs.

| `rules/`
| Machine-checkable rules.

| `diagrams/`
| PlantUML sources and their rendered SVG files.

| `jurisdictions/`
| Comparison data per jurisdiction. `baseline.yaml` lists the compared requirements.
|===
